# 단일 행 Composer 실험

별도 브랜치 `experiment/fluid-composer`에서 공식 `experimental_composer` slot을
`bb-chat-ui/fluid-composer` renderer로 교체한다. 기본 Composer의 입력 엔진과
SDK 연결을 유지하고 배치와 높이 전환은 `FluidComposerBody`가 소유한다.

## 확인할 동작

- 빈 입력과 한 줄 초안은 한 줄 높이이며, 포커스만 바뀌어도 커지지 않는다.
- 줄바꿈·자동 줄바꿈·삭제에 따라 자연 높이로 전환한다. 긴 입력은 내부에서 스크롤한다.
- `+`, 모델, 음성, 전송·중단과 멘션·인용·첨부가 기존 엔진과 연결된다.

상단 정보 pill과 Project·Branch·Permission·Context 줄, 모델 선택은 컴포저 우측의
원형 `정보와 설정` 버튼으로 펼친다. 기존 정보 줄과 footer는 원래 위치에서 표시하고
모델 선택은 입력 위의 frost 영역에서 연다. host 컨트롤은 mount한 채 유지해 초안과
선택 상태를 보존한다. Escape와 같은 버튼으로 닫으며 다른 컴포저의 표시 상태는 바꾸지 않는다.
승인·질문·비밀 입력 같은 진행에 필요한 요청 카드는 유지한다.
대기 메시지 편집기는 기존 배치를 유지한다. 이 실험은 성능 개선을 주장하지 않는다.

## 구조

- `FluidComposer.tsx`: 공식 slot 진입점. kit `useDeviceChrome()`으로 phone을 판정한다.
- `FluidComposerBody.tsx`: 새 배치 및 로컬 크기 관찰 수명.
- `../lib/fluid-composer-height.ts`: 내용 크기가 바뀔 때만 높이를 갱신한다. kit의
  `EASE.out`으로 입력 높이·모서리는 120ms, 옵션은 320ms를 사용하며 reduced motion 변경을 즉시 반영한다.
- `../lib/fluid-composer.ts`: 실험 전용 표면·글자·버튼 배치와 숨김 규칙.
- `src`: 공식 Composer 엔진. fluid 배치·높이 관찰 제외와 음성·내부 옵션 모드 연결을 추가했다.
- `components`, `lib`: 같은 upstream revision의 공식 UI registry 구성요소.
- `tiptap-blockquote`: 공유 ProseMirror state를 사용하는 Tiptap 원본. node_modules를
  수정하거나 설치 시 임의 patch를 적용하지 않는다.

## 출처와 검증

출처와 원본 해시는 `UPSTREAM.json`에 있다. 실행 중인 nightly의 GitHub Actions
revision `916d684ac23d0b0de82c09cfc7553a50287d2188`과 일치하는 소스를 사용했다.
오래된 소유권 전환 실험의 broker는 포함하지 않는다.

`npm test`, `npm run test:composer`, `npm run typecheck`, `bb plugin build .`로 검증한다.
upstream의 큰 paste 시간 실험 세 개는 기존 `PROMPTBOX_PERF=1` 조건을 그대로 유지한다.
실제 화면과 동작은 phone·desktop browser로 별도 확인하며, 사용자 실기기 판정이 필요하다.

## 입력 상자의 스쿼클

한 줄 입력은 desktop 24px·phone 26px의 기존 반원을 유지한다.
CSS 스쿼클 지원 브라우저에서는 여러 줄 입력의 실제 clip에만 시각적 비교 배율 2.11을 적용한다.
desktop은 24px → 50.6px, phone은 26px → 54.9px이며 소수 첫째 자리에서 반올림한다. 정확한 곡선 환산식은 아니다.
기존 multiline 상태를 실제 clip에 전달하며 새 관찰자를 추가하지 않는다.
배경 frost 면과 음성 glow도 실제 clip의 모서리를 따르며 옵션 카드와 원형 버튼은 그대로다.
미지원 브라우저는 기존 반지름과 둥근 모서리를 유지한다. 별도 Composer 플러그인의 입력 엔진과 모션은 합치지 않는다.

## 현재 음성 UI: 컴포저 하단 glow

기본 컴포저의 너비·높이·모서리를 유지하고 기존 입력 영역에 받아쓰기를 표시한다.
한 줄은 desktop 48px·phone 52px이며 내용이 길어질 때만 기존 높이 전환과 상한을 따른다.
하단 세 영역의 radial gradient는 BB `--ring` 색을 사용한다. 과거 음량이 시간차로 전파되어
영역마다 번짐과 농도를 바꾸고 위치는 천천히 흐른다. 기존 240ms 음량 추종과 최대 30Hz
갱신을 공유하며 전용 frame loop·추가 AudioContext·배경 blur를 만들지 않는다.
빛은 기존 radius 안에 clip하며 pointer를 받지 않는다. reduced motion은 정적인 빛이다.

음성 버튼을 누르는 순간 녹음을 시작한다. 250ms 이상 누른 뒤 놓으면 마이크를 즉시 해제하고
최종 data를 받은 뒤 전사문을 입력창에 넣는다. 이 경로는 자동 전송하지 않는다.
짧게 클릭하면 손을 떼어도 계속 녹음한다. 다시 클릭하면 마이크를 즉시 해제하고 기존
중지·전송을 기본 버튼 크기로 표시한다. 최종 data가 도착하기 전에는 선택을 잠그며,
이 클릭 경로는 선택 전에는 변환하지 않는다. 키보드·보조기술의 클릭도 같은 유지 모드다.
pointer capture로 버튼 밖에서 손을 떼는 경우를 받고, pointer 취소·capture 상실은 녹음을
취소한다. 권한 대기 중 긴 누름이 끝나면 취소하며 늦게 도착한 stream도 정리한다.
자동 전사가 실패하면 녹음 파일을 보존하고 기존 중지·전송 선택을 표시해 닫거나 재시도한다.
누르는 동안은 기본 중지 사각형 대신 같은 자리의 02A 링 순차 진입·02B 음량 반응을 표시한다.
짧게 누른 뒤 손을 떼면 컴포저 안에 1px 막대 49개를 넓게 펼친다. 받아쓰기 문장이 있으면
막대 아래에 표시하며 없으면 기존 한 줄 높이를 유지한다. 두 표시와 glow는 하나의
AudioContext·분석기·최대 30Hz 갱신을 공유하고, 모드만 바뀔 때 녹음이나 분석을 재시작하지 않는다.
막대의 여백은 받아쓰기 스크롤 밖에 두어, 긴 문장을 끝으로 이동해도 막대와 글이 겹치지 않는다.
시작과 중지의 기존 phone selection 햅틱은 실제 활성화마다 한 번만 전달한다.
초안 보존·전송 성공 때 비우기·실패 때 복원과 Escape·화면 이탈·잠금·해제 정리는 유지한다.
`FluidVoiceControl`의 `composer` 표현과 `FluidVoiceWaveform`의 `glow` 표현이 현재 앱 경로다.
SDK host·마이크·인식·외부 액션만 검수 데이터로 바꾸는 실제 엔진 데모를 함께 유지한다.

## 보존된 링 레퍼런스

아래 링·물방울 표현은 디자인 레퍼런스와 독립 데모에 보존한다.


빈 초안의 주 액션은 음성 버튼이다. 텍스트나 첨부가 있으면 기존 전송 버튼을 쓴다.
클릭하면 음성모드가 시작되고 손을 떼어도 녹음한다. 컴포저 윤곽·입력·받아쓰기·첨부·
보조 정보·+·정보와 설정을 숨기고 02B의 21개 SVG 링으로 된 구를 가운데 표시한다.
기존 foreground를 사용하고 실제 음량을 240ms로 완만하게 추종한다. 구의 방향과 각 링의
중심은 고정하며 음량에 따른 링 확대는 최대 48%로 하되 전체 중심은 움직이지 않는다.
표시 SVG는 desktop 72px·phone 80px 이내이며 기본 구 지름은 약 57px·63px다.
강한 음량으로 커진 링은 SVG 경계에서 자르지 않고 기존 음성 단계의 공간 안에 표시한다.
기존 frost 면은 채팅 하단 전체 폭의 14px 배경 블러 한 겹으로 재사용하며,
그림자·카드 윤곽 없이 위로 갈수록 옅어지는 linear mask를 적용한다.
기존 로컬 ResizeObserver로 현재 pane의 폭·가로 위치·하단 경계에 맞추며, 원래 composer 폭이나
가로 스크롤은 늘리지 않고 옆 패널로 번지지 않게 한다. 진입·퇴장은 02A처럼 각 링 전체가
순서대로 나타나고 사라지는 native Animation이다. 진입은 27ms 간격·260ms fade,
퇴장은 21ms 간격·180ms fade이며 말하는 동안에는 02B의 크기 반응을 사용한다.
다시 누르면 마이크는 즉시 멈추고 마지막 링이 사라진 뒤 중지·전송을 선택한다. 모션은
reduced motion 변경·중지·unmount 때 정리한다. 음량에 따른 밝기·굵기 변화는 작게 두고 크기 변화를 주 표현으로 삼는다.
각 링의 앞쪽과 뒤쪽은 실제 투영 깊이를 바탕으로 한 currentColor gradient로 구분한다.
공기 원근법의 농도는 음량과 독립적으로 고정하고 gradient 위치만 커진 링에 맞춘다.
표시에는 2% 이하의 미세 음량을 억제하고 제곱근 곡선을 적용해 작은 발화의 대비를 높인다.
이 보정은 그림에만 적용하며 원본 녹음과 변환에는 적용하지 않는다.
시간은 링 사이 45ms의 전파를, 각 링의 크기는 과거 음량을 정한다. 현재 음량이 작아져도
앞선 큰 음량은 링을 따라 이동하며 감쇠한다. 최근 64개 표본만 메모리에 보관하며
녹음 스트림과 기존 frame loop를 재사용한다. 갱신은 초당 최대 30회이며 WebGL은 쓰지 않는다.
링 밀도가 늘어도 구 전체의 전파 시간·감쇠와 등장·퇴장 총 시간은 유지한다.

구를 한 번 누르면 마이크와 미리보기를 즉시 중지한다. 마지막 음성 data를 받기 전에는
선택 버튼을 잠그고, 완료된 뒤 왼쪽 중지·오른쪽 전송 pill을 활성화한다.
pill은 desktop 80×48px·phone 90×52px이며 기본 한 줄 컴포저와 높이를 맞춘다.
녹음과 선택 상태의 바깥 높이는 같고 최종 가로 간격은 16px다.
460ms kit 물방울 곡선으로 면이 뭉친 뒤 벌어지며 가운데 연결부가 가늘어져 사라진다.
장식 면만 늘이고 글자·아이콘·터치 영역은 scale하지 않는다.
분리에는 추가 blur·filter·frame 타이머·전역 관찰을 사용하지 않는다.

선택 전에는 변환하거나 전송하지 않는다. 중지는 변환 결과를 입력에 남기며 전송은
기존 전송 액션으로 보낸다. Escape·화면 이탈·호스트 잠금·unmount는 녹음을 취소한다.
입력 엔진과 설정 컨트롤은 mount를 유지하고 종료 시 컴포저와 열려 있던 정보를 복원한다.
키보드로 녹음을 중지하면 마지막 data를 받은 뒤 중지 버튼으로 포커스를 옮긴다.

`lib/hold-voice.ts`가 녹음·완료·변환을 소유한다. 기존 `release`로 마이크를 멈추고
선택한 뒤에만 `finish`로 BB 변환과 전달을 시작한다. 이전 요청이 늦게 도착하면 무시한다.
BB 변환은 `useSdk().system.transcribeVoice`를 사용한다. 실패한 녹음은 메모리에 보존해
전송으로 재시도하거나 중지로 닫는다. 디스크에는 저장하지 않는다.
시스템 음성 단축키로 시작한 native 녹음은 기존 막대를 유지한다.

`FluidVoiceWaveform`은 자신의 AudioContext·frame만 정리하며 원본 track은 녹음 session이
소유한다. 중지 뒤에는 마지막 구 모양을 잠시 보존해 fade한다. reduced motion에서는
정적인 구이며 연결부·면의 모션 없이 버튼 모양을 즉시 바꾼다. 새 녹음·motion 변경·
시간 역행·긴 공백은 음량 기록을 초기화하며 분석 실패 때도 정적인 구와 녹음을 유지한다.
일반 입력 높이·위치 morph는 120ms 감속 곡선을 사용한다.

브라우저가 SpeechRecognition을 지원하면 녹음 중 받아쓰기 미리보기를 수집하지만
음성모드에서는 표시하지 않는다. 실제 editor는 mount한 채 초안을 보존하고
중지·전송을 선택한 뒤에만 BB 최종 결과를 삽입한다.
발화 결과가 있는 자연 종료 뒤에는 이어서 인식하며, 빈 종료는 반복하지 않는다.
미지원·거부·오류·빈 종료 때는 녹음을 유지하고 중지·전송에서 BB 변환을 사용할 수 있다.
브라우저 미리보기와 BB 최종 변환은 서로 다른 음성 서비스를 사용할 수 있다.

desktop의 전송·옵션 그룹은 바깥을 하나의 둥근 pill로 유지한다.

## 컴포저 내부의 추가 옵션

단일 행 실험의 `+`는 별도 popover·drawer 대신 같은 form의 내부를 옵션 화면으로
전환한다. `bindFluidComposerHeight`의 320ms 높이 전환을 공유한다.
왼쪽 토글은 별도 원형 frost 면이며 오른쪽 8px 간격의 카드에 옵션을 표시한다.
목록이 길면 전체 컴포저의 상한 안에서 목록만 스크롤한다.

한 줄 입력의 모서리는 desktop 24px·phone 26px(기본 높이의 절반)이며 옵션 화면은
26px다. 투명한 창 안의 카드 frost 면을 오른쪽으로 translate하고 창의 둥근 모서리로
오른쪽 끝을 제한한다. 면의 translate·높이·모서리와 실제 두 내용의 opacity·translate를
320ms·kit easing으로 함께 전환한다. 내용을 복제하거나 글자를 scale하지 않는다.
닫힐 때 옵션 화면은 최대 320ms 동안만 유지하며 즉시 inert·aria-hidden을 적용한다.
진행 중 반대로 열면 기존 DOM과 CSS 전환을 이어가고 이전 종료 예약은 취소한다.
동작 줄이기 설정·기기 이탈 때 예약과 listener를 정리한다.

입력 엔진과 첨부는 mount한 채 숨겨 초안·커서를 보존하고, 옵션 화면에서는 입력·전송을
잠근다. 같은 자리의 `×`·Escape로 돌아오면 선택 위치에 포커스를 복구한다. 같은 화면에서의
데이터 갱신은 모드를 유지하고 스레드·Composer 변경·호스트 잠금·native 음성 시작은
옵션을 닫는다.

Attach files는 기존 파일 입력을 한 번 열며 Skills·Plan·Goal은 기존 명령 삽입을
실행하고 입력 화면으로 돌아온다. 다른 플러그인의 항목은 공개 `MenuEntry`를
사용해 소유 플러그인에 바인딩된 Composer API·가용성·아이콘·설명·실행·오류 처리를
보존한다. registry의 공유 메뉴 context에서 버튼 표시 분기만 사용하며 기기 판정이나
별도 drawer를 만들지 않는다. 플러그인이 다른 UI로 옮긴 포커스는 보존한다.
플러그인 선택 후에는 입력 잠금을 해제한 다음 같은 scope의 host 선택 API로
포커스를 복구한다. 다른 스레드·Composer로 전환되면 오래된 복구 요청을 버린다.
Arrow 키와 Home·End로 활성 항목을
탐색할 수 있다. 모델·전송 메뉴와 플러그인이 따로 여는 UI는 기존 경로를 유지한다.

## 고정 토글과 여러 줄 입력

`+`는 입력·옵션 레이어 밖에 한 번만 mount하고 왼쪽 아래에 고정한다. 메뉴를 열면
같은 glyph를 45도 회전해 `×`로 바꾸며, 메뉴 헤더 없이 토글 오른쪽 공간에 항목을
배치한다. 빈 목록·모두 비활성인 목록에서도 토글 또는 Escape로 닫을 수 있다.

여러 줄 입력은 버튼 위의 전체 폭으로 펼치고 버튼들은 하단에 유지한다. 첨부는 그
입력 줄 위에 둬 토글과 겹치지 않게 한다. 한 줄이더라도 접힌 열의 폭에 맞지 않으면
펼침을 유지하고, 짧아지면 다시 한 줄로 돌아간다. clipped mention은 숨겨진 긴 label이
아닌 바깥 box의 폭으로 판단한다. `draftText`·입력 준비 변화와 현재 row·버튼의 크기
변화만 한 frame에 묶어 측정하며 transcript를 관찰하지 않는다.

입력 배치가 바뀌면 같은 실제 editor의 위치 차이만 120ms·kit 감속 easing으로 옮긴다.
여러 줄로 펼칠 때는 바깥 높이와 같은 감속 곡선으로 이동해 커서가 표면보다 먼저
올라가지 않게 한다. 한 줄로 축소할 때는 기존 감속 곡선을 유지한다.
문자·버튼의 scale이나 복제는 없으며, 빠른 역전은 현재 보이는 위치에서 이어간다.
reduced motion·해제 시 위치 전환과 예약 frame을 취소한다.

위치 전환 중 후속 Enter나 `beforeinput`이 들어오면 실제 editor의 이동 모션을 즉시
끝낸다. 진행 중인 높이 transition도 그때만 마쳐 커서가 작은 창 위로 잘리지 않게 한다.
입력 사건은 취소하거나 지연하지 않는다. 후속 입력이 없는 기본 120ms 감속 모션과 이미
펼쳐진 입력의 이후 높이 전환은 유지하며 두 listener는 해당 컴포저에만 연결한다.

여러 줄 본문은 좌우 20px·위 16px를 비운다. padding이 바뀌어도 실제 글자 위치를
기준으로 이동량을 구해 전환 시작 때 글자가 튀지 않게 한다.

## 전체 높이 상한

phone은 35dvh, desktop은 40dvh를 전체 높이 상한으로 쓴다. host의 `maxHeight`가 더
작으면 그 값을 쓰되 최소 96px는 확보한다. 본문만 제한해 버튼 높이가 상한 밖으로
더해지지 않도록 내용은 flex·grid의 남은 공간에서 줄어들고 editor scroll 영역만
스크롤한다. 옵션 목록도 같은 상한을 공유하며, 첨부·실패 음성 같은 보조 정보는
따로 스크롤할 공간을 제한해 하단 조작을 남긴다.

기기별 CSS 변수는 기존 루트 device 속성으로 선택한다. viewport·host 상한 변경도
CSS가 반영하고 기존 내용 ResizeObserver가 전환 높이를 갱신한다. 높이 계산을 위한
새 전역 observer나 frame별 DOM 검색은 추가하지 않는다.

editor에는 여러 줄 버튼 공간을 뺀 최대 높이를 처음부터 적용한다. 이 제한이 없으면
긴 붙여넣기 직후 Tiptap이 스크롤을 맞춘 뒤 배치가 바뀌어 마지막 줄이 가려진다.
컴포저 전체에서 wheel·한 손가락 touch를 내부에 유지한다. `bindComposerScrollBoundary`를
입력과 메뉴에서 공유하며 내부에 해당 방향의 스크롤 여유가 있으면 native 동작을
유지한다. 짧은 내용·끝·버튼 주변 여백에서는 기본 스크롤 연쇄도 차단한다.
Ctrl+wheel·pinch는 그대로 전달하고 listener는 해당 컴포저와 메뉴 해제 때 제거한다.

열린 `+` 메뉴도 같은 경계 처리를 사용한다. 스크롤하면 메뉴의 fade를 즉시 끝내며
메뉴를 닫거나 해제하면 해당 메뉴의 listener를 제거한다.

## 키보드와 옵션 전환

`+`를 누르면 기존 메뉴의 포커스 복원을 요청하지 않고 예약된 입력 포커스 복원도
취소한다. editor의 DOM 포커스를 먼저 동기적으로 해제한 뒤 같은 입력 사건에서
옵션을 연다. 키보드가 닫히는 시간은 기기가 결정하며 별도 고정 대기나 viewport
감시를 추가하지 않는다. 옵션의 첫 항목은 목록을 맨 위로 놓고 preventScroll로
포커스해 키보드 전환 중 바깥 스크롤을 요청하지 않는다.

열린 옵션의 터치 영역은 desktop 48px·phone 52px다. 보이는 frost 면은 그 안쪽에
4px를 비워 desktop 40px·phone 44px로 둔다. 보이는 원과 카드의 간격은 8px를
유지하고 기호 중심은 그대로 둔다. 입력 상태의 기존 버튼 크기와 다른 음성·전송
버튼은 유지한다.

## pill 모션 재사용

`FluidComposerToggle`이 kit의 `pressPop`을 frost 면에만 적용한다. 누르는 동안 120ms,
놓으면 380ms의 물방울 easing을 쓰며 기호와 터치 영역은 scale하지 않는다. 포인터
취소·이탈·capture 상실·비활성·해제·reduced motion은 이 면의 모션을 정리한다.
새 전역 포인터 listener나 capture는 추가하지 않는다.

기호는 같은 두 선을 45도 회전하되 길이를 12px에서 20px로 늘린다. 회전으로 가로·세로
투영 폭이 작아지는 것을 보정하며, 선의 높이와 회전만 기존 320ms로 이어간다.

카드의 레이아웃 morph는 유지하고 메뉴 내용은 목록 전체에 260ms opacity fade를
한 번만 적용한다. 항목별 반동·translate·scale·지연은 두지 않으며 비활성 글자의
흐림도 유지한다. 데이터 갱신마다 다시 실행하지 않는다. 닫기·해제·reduced motion은
즉시 취소하고, 포인터·wheel·touch scroll·키보드 조작도 fade를 끝내 실제 조작을
우선한다. 입력 높이는 120ms이며 옵션 전환과 퇴장 레이어 보관은 기존 320ms를 유지한다.

`+`·`×`·모델·전송 옵션의 실제 활성화는 phone의 haptic capability가 있을 때
selection 햅틱을 한 번 낸다. 기존 음성·메뉴 선택·전송 햅틱에 중복 pulse를 붙이지 않는다.

입력 글자는 desktop 14px·phone 16px이고 줄 높이는 24px다. 한 줄 기본 배치와
모션은 이 글자 크기를 줄이지 않는다.

여러 줄 입력의 확장·축소는 120ms·kit 감속 곡선으로 바로 출발한다.
실제 clip의 높이·반지름·corner-shape를 같은 시간·곡선으로 전환한다. 옵션은 기존 320ms를 유지한다.
기존 높이 ResizeObserver만 재사용하고 빠른 추가 입력은 현재 보이는 높이에서
이어 간다. 하단 버튼과 높이 상한·reduced motion 처리는 유지한다.
