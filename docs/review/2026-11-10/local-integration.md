# 로컬 main·PR 통합 검증

로컬 기준은 `78807ccd091c0147ec49017ab8b83f5916edde75`, 원격 PR #1은 `3a6e9831ac53f04f1b8af2129f0f0c1136010844`, #2는 `ee41692243212630635864dafab7d19b9397c5bc`다. 사용자 선택에 따라 디자인·트랜지션은 원격을 기준으로 하고 로컬 음성과 iPhone 입력 수정을 유지했다. Chat UI PR #17의 정보 행 폭 예약과 함께 쓸 수 있다.

## 보존과 수정

- 통합 전 음성 관련 파일 14개는 로컬과 PR에서 같았다. 녹음 엔진, 실시간 미리보기, 음량 파형, hold·toggle, 전사 삽입, 전송을 유지했다. 녹음 중에는 새 모델 설정 버튼만 숨긴다.
- 기존 main과 통합본 모두에서 즉시 전사 응답 뒤 손뗌의 호환 click이 새 전송 버튼으로 넘어가는 경합을 재현했다. 같은 click 한 번만 막으며 다음 포인터·키보드 입력 및 unmount에서 guard를 정리한다. 타이머는 추가하지 않았다.
- 이전 scope의 확인 응답은 새 scope의 포커스를 가져가지 않는다. 유효한 같은 scope의 확인만 설정 버튼에 포커스를 복구한다.
- 일반 Effort도 새 스레드의 projectId를 조회 경로에 전달한다.
- 모델·옵션 화면에서 숨긴 toolbar와 빌린 정보 행은 inert로 처리한다. 닫힘·교체·unmount에서 이전 inert 상태를 복구한다.
- 전역 `@property` 대신 항목의 transform·opacity를 직접 보간한다. PR의 260ms·열기/닫기 곡선과 열린 휠의 즉시 스크롤을 유지한다. 활성 owner의 스타일 공유와 마지막 owner 해제 시 즉시 정리도 유지한다.

## 검증 범위

각 오류는 수정 전 실패 검사 또는 브라우저 재현을 남긴 뒤 수정했다. 전체 테스트와 typecheck·build, desktop·phone Chromium에서 설정 확인·취소·숨은 버튼·클릭 녹음·hold 종료·전사 삽입을 확인했다. 녹음 장치와 전사는 검수용 대역이며 실제 사용자 메시지 전송은 하지 않았다. 기존 skip 3개는 변경하지 않았다.

합성 대화 5,000행에서 표본당 Composer를 세 번 재생성했다. 3묶음 ABBA, phase당 예열 2회·유효 표본 6개로 각 비교의 양쪽 36표본을 수집했다. PR 통합본 대비 수정본의 TaskDuration 중앙값은 213.82→63.61ms, long task는 108→0이었다. 별도 현재 main 대조는 52.18→63.31ms로 약 11ms(+21%)의 추가 비용이 남는다. 표본 전체가 세 번 재생성한 합계이며 실제 BB 스레드 전환·paint 시간은 아니다. 마지막 음성 click guard는 비활성 입력기 재생성 경로를 바꾸지 않는다.

실제 iPhone 녹음·키보드·햅틱과 전체 BB에서의 성능·시각 동등성은 미확인이다. phone·desktop 캡처는 합성 SDK host의 제품 컴포넌트이며 실제 설치 화면의 캡처가 아니다. 소스·브라우저 도구·fixture·bundle hash와 원본 로그는 작업 thread storage에 보존한다. 실제 provider 선택과 설치 bundle 변경은 별도로 확인해야 한다.
