# 컴포저 모델·Effort 시안

제품에 적용하지 않은 디자인 자료다. [보관된 갤러리](gallery.html)는 외부 파일이나 서버 없이 열 수 있다. 공급자·모델·전송은 합성 데이터와 검수용 동작이다. 실제 설정을 변경하거나 메시지를 보내지 않는다.

| 시안 | 동작 |
| --- | --- |
| 01 눈금 줄 | 입력줄을 Effort 눈금으로 바꾸고, 같은 자리에서 모델을 고른다. |
| 02 캡슐 | 작은 설정 버튼이 양옆으로 늘어나 모델과 Effort 조절기가 된다. |
| 03 전송 버튼 | 전송 버튼을 길게 누르고 끌어 Effort를 고른다. |
| 04 아래 줄 | 여러 줄 입력의 아래 줄에 모델과 Effort를 표시한다. |
| 05 목록 | 컴포저가 위로 자라 모델 목록과 Effort 눈금을 담는다. |
| 06 슬롯 | 컴포저 크기와 위치를 유지하고 공급자·모델·Effort를 세로로 굴린다. |

01–05는 이후 비교에 쓸 수 있도록 그대로 보관했다. 06도 수정 전 상태를 함께 남겼다. 휴대폰 320·360·390과 데스크톱, 라이트·다크, 빈 초안·한 줄·긴 글을 비교할 수 있다.

기준 제품 커밋은 `b845b6868fcb2663ef263bed6a6b2780cf3042f2`다. HTML SHA-256은 `802ef29b916d5c6ce86a194fdd2e1a3d53af20299cf7fc5ee16c726f270a6933`다. 원본 검사 결과는 67개 통과, 페이지 오류 0개다. 실제 폰과 스크린리더 검증은 하지 않았다.

`gallery.tsx`와 `gallery.css`는 수정 가능한 원본이다. TSX의 `__SNAP__`는 기준 커밋에서 추출한 제품 소스 경로로, `__COMMIT__`는 표시용 커밋으로 치환하는 빌드 입력이다. `gallery-manifest.json`에 사용한 제품 파일의 해시를 기록했다. HTML은 이미 묶인 독립 자료이므로 소스 추출 없이 바로 볼 수 있다.

06의 보관본에는 아래 항목이 아직 없다. 이어지는 시안에서 비교한다.

- 01과 같은 확인 버튼 등장과 공급자 변경 시 핸드오프 아이콘.
- Fast 모드의 번개 표시.
- 컴포저 위에서 선택하는 슬롯·현재 모델/Effort 배치 비교.

보관본의 06은 아래 칸을 모두 보이게 하려고 데모 하단 여백을 84px로 넓혔다. 실제 화면 하단에 놓으면 아래 칸 일부가 잘릴 수 있으므로 실기기 검증이 필요하다.

## 이어서 검토하는 06

`slot-review.tsx`와 `slot-review.css`는 06만 남긴 다음 시안이다. 제품 파일은 변경하지 않는다.

- 확인 버튼은 01과 같은 위치와 표면에 나타나며 같은 `eventHop`을 쓴다. 설정 버튼을 회전하며 옆으로 이동시키던 동작은 뺐다.
- 슬롯을 열 때의 공급자와 다른 공급자를 고르면 확인 표시를 핸드오프 화살표로 바꾼다. 원래 공급자로 돌아오면 확인 표시를 복구한다.
- 모델 칸 옆 번개 버튼이 Fast를 켜고 끈다. 켜진 상태는 닫힌 설정 버튼의 작은 번개에도 표시한다. Fast 가용성과 상태는 검수용이며 실제 공급자의 지원 여부를 뜻하지 않는다.
- 컴포저 위 토글로 `06 슬롯`과 `현재 모델·Effort 배치`를 비교한다. 입력 엔진을 다시 만들지 않아 직접 작성한 초안을 유지한다.

다음 명령을 저장소 루트에서 실행하면 `thread-storage`에 독립 HTML과 해시 기록을 만든다. 설치된 `../bb-plugin-codes/node_modules/esbuild`를 사용하며, 기준 제품 소스는 Git에서 읽는다. 새 의존성을 설치하지 않는다.

```powershell
node docs/design-references/composer-model-effort/build-review.mjs "$env:BB_THREAD_STORAGE\composer-06-review"
```

생성된 `index.html`은 파일로 바로 열 수 있다. 실제 핸드오프와 Fast 설정 변경은 실행하지 않는다. 실제 적용 여부와 최종 모양은 별도로 결정한다.

검수에서는 작성한 초안의 유지, 두 배치의 전환, 확인·핸드오프 아이콘 전환, 공급자별 Fast 상태, 키보드 선택과 Escape, 한 줄 입력의 52px 높이를 포함한 14개 동작을 확인했다. 핸드오프 조건을 반대로 만든 별도 빌드도 같은 확인 조건에서 거부되는 것을 확인했다.

`npm run typecheck`는 통과했다. 전체 `npm test`는 785개 중 783개가 통과했으며, 이번 변경과 무관한 `composer-info`의 글자 크기·PR 메뉴 검사 2개가 실패했다. 이 두 검사는 단독 재실행에서 모두 통과했다. 실제 폰의 아래 칸 잘림, iOS 관성 스크롤·햅틱과 실제 Fast·핸드오프 연결은 확인하지 않았다.
